# Synthesis PPA and Physical-Design Preparation Plan

> **For the implementation agent:** Execute this plan task by task and keep the verification evidence generated by each task.

**Goal:** Prepare a reproducible, honest backend handoff for the AEGIS-RISC DMA firewall, with a valid single-clock timing contract, closed-loop RTL checks, deterministic source manifests, a generic synthesis/PPA baseline, and a PDK-gated physical-design entry point.

**Scope:** The production backend target is `rtl/dma_bus_firewall.v`. The current repository does not contain a complete PDK, Liberty/LEF set, SPEF, or a synthesizable full-SoC top, so physical signoff must remain gated until those external inputs are supplied.

**Verification baseline:** Verilator lint, Icarus directed simulations, bounded SymbiYosys proofs, and Yosys hierarchy/statistics. Do not label generic synthesis as signoff PPA or claim DRC/LVS/timing closure without foundry collateral.

## Tasks

### 1. Close RTL backend-facing behavior

**Files:** `rtl/fw_mtd_engine.v`, `rtl/dma_bus_firewall.v`, `tb/tb_aegis_soc.v`

- Make the Level-1 MTD jitter signal usable as a request interlock, so it can affect issue timing rather than only being observed internally.
- Use the active MTD key in the honey-pot target calculation while preserving a word-aligned address inside the configured honey-pot page.
- Strengthen the end-to-end test to observe jitter/interlock activity and verify that the dynamic honey-pot target is not a fixed address.
- Keep the existing AXI ordering, drain, and reset semantics intact.

### 2. Establish the synthesis and timing contract

**Files:** `backend/sources.f`, `constraints/dma_bus_firewall.sdc`, `backend/README.md`

- Record the exact production top and deterministic RTL source order.
- Add one valid `clk` constraint, realistic input/output delay assumptions, and an asynchronous-reset false path using only ports that exist on the production top.
- Document the top-level scope, assumptions, required PDK inputs, and the distinction between generic estimates and signoff results.

### 3. Add reproducible backend entry scripts

**Files:** `backend/run_synth_ppa.ps1`, `backend/run_openroad.ps1`, `backend/openroad_init.tcl`

- Provide a PowerShell wrapper for Yosys generic synthesis that emits a netlist, JSON, statistics, and a machine-readable run manifest under `output/ppa/`.
- Provide a physical-design wrapper that validates OpenROAD, LEF, Liberty, and SDC inputs before running; fail closed when any required collateral is absent.
- Keep generated outputs out of RTL and make the commands usable from the repository root.

### 4. Run and record the readiness checks

- Run DMA and firewall lint, the relevant directed simulation/formal suites, and the Yosys synthesis baseline.
- Inspect generated statistics and verify that no stale `pclk`/`presetn` constraints or missing source paths remain.
- Report remaining external blockers explicitly: PDK/corners, LEF/Liberty, SPEF, DRC/LVS decks, and the absent full-SoC production top.

## Completion criteria

- The backend source manifest resolves every file and has no testbench-only source.
- The SDC parses conceptually against the actual `dma_bus_firewall` ports and contains no phantom clock/reset ports.
- RTL checks pass for the touched modules; directed tests demonstrate the MTD interlock and dynamic honey-pot behavior.
- Generic synthesis completes and produces reproducible area/cell statistics.
- Physical design is either run with validated collateral or stops with a clear missing-input report; no synthetic signoff evidence is produced.
