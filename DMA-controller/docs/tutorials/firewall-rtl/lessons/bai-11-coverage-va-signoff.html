Coverage cao không chứng minh test đúng; review hole và illegal/ignore bins vẫn bắt buộc.

Synthesis, timing và CDC

  • Lint: width, latch, multi-driver, undriven, unreachable state, reset.
  • Synthesis: named top và complete source closure, không black box.
  • STA: named target library/FPGA, clock, corner và constraints.
  • CDC: thiết kế nội bộ một clock; vẫn phải chứng minh top-level sources thuộc clk hoặc đã synchronize.
  • PPA chỉ có ý nghĩa khi ghi rõ tool/version/library/corner/constraints.

Gate trung thực

Không có coverage tool       => G5 BLOCKED_TOOLING
Không có target/corner       => G6 BLOCKED_EXTERNAL_INPUT
Không có SoC trust evidence  => G7 BLOCKED_EXTERNAL_INPUT

G0–G3 PASS không cho phép gọi toàn bộ kiến trúc đã sign-off.

Lab cuối khóa

  1. Rerun spec-lint và toàn regression từ source list sạch.
  2. Kiểm tra stale names/ports/draft/evidence bằng repository search.
  3. Map Requirement → Module → Interface/Register/FSM → Test → Expected → Evidence.
  4. Chạy coverage/formal/synth/STA nếu tool/target có; nếu không ghi blocker cụ thể.
  5. Tạo release report gồm source hash, tool versions, logs, waivers và remaining risk.
  6. Review riêng reset, denied isolation, exact beats, snapshot và priority.

Exit gate

  • Không requirement nào vô chủ.
  • G0–G7 đều có PASS/FAIL/BLOCKED và căn cứ.
  • Không stale evidence từ draft đã xóa.
  • Release report không tuyên bố vượt quá evidence.

Câu hỏi tốt nghiệp

  1. Functional coverage 100% có đủ sign-off security không?
  2. Vì sao single-clock IP vẫn cần kiểm tra CDC ở boundary?
  3. Điều kiện tối thiểu để tuyên bố G6 PASS là gì?
