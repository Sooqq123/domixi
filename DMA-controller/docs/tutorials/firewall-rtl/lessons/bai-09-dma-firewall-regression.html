Bài 09 — DMA–Firewall subsystem regression

Mục tiêu: chứng minh DMA và Firewall phối hợp đúng trên end-to-end traffic, abort, backpressure và trust profile; đồng thời tạo evidence tái lập được.

Đọc bắt buộc

  • architecture_overview.md: DMA data/control flow.
  • verification_test_plan.md: toàn bộ Firewall/DMA integration test IDs.
  • requirements_traceability.csv.
  • verification_evidence_manifest.csv.

Testbench topology

APB driver ──> DMA controller ──AXI──> Firewall ──AXI──> memory model
                   │                    │
                   └── context ─────────┘
monitors: APB + both AXI boundaries + context + IRQ + scoreboard

Memory model phải hỗ trợ backpressure, response error, ID mismatch và framing injection có kiểm soát. Scoreboard không được dựa vào DUT internal state để tính expected result.

Regression tiers

  • Smoke: reset, legal copy, ACL deny.
  • Protocol: W-before-AW, ID mismatch, RLAST/WLAST errors.
  • Security: snapshot stall, same-cycle revoke, overlap, full containment, FW_EN semantics.
  • Stress: random ready/valid, concurrent APB/context, repeated seeds, watchdog.

Evidence contract

Mỗi run phải ghi source list/hash, simulator/version, command, seed, timestamp, PASS/FAIL và log path. File `.vvp` không kèm source/hash không đủ để tái lập.

Lab

  1. Tạo tb_soc_dma_firewall_top.v từ source hiện tại; không dùng binary cũ.
  2. Viết script compile một source list duy nhất và fail-fast.
  3. Map từng requirement Firewall tới ít nhất một test và expected result.
  4. Chạy smoke trước, sau đó protocol/security/stress.
  5. Lưu seed của mọi failure; rerun failure bằng đúng seed.
  6. Rerun toàn unit suite sau mỗi integration fix.
iverilog -g2012 -Wall -s tb_soc_dma_firewall_top ...
vvp build\tb_soc_dma_firewall_top.vvp +SEED=12345

Exit gate

  • Regression script trả mã khác 0 khi compile/test fail.
  • Mọi test có explicit PASS marker và timeout.
  • Không requirement nào không có test/evidence owner.
  • Stress chạy nhiều seed tái lập được, không deadlock.

Câu hỏi kiểm tra

  1. Vì sao scoreboard không nên đọc internal allow signal để tính expected?
  2. Một random failure không lưu seed có giá trị evidence thế nào?
  3. Khi integration fix top, vì sao phải rerun unit tests?
