Bài 06 — Denied-read generation

Mục tiêu: tự sinh đúng ARLEN+1 R beat cho request bị deny, với RID/RRESP/RLAST ổn định và không phát AR ra matrix.

Đọc bắt buộc

  • fsm_specification.md: R_DRAIN_IDLE/GEN.
  • signal_list.csv: acl_r_*, r_drain_*.
  • verification_test_plan.md: exact read beats và backpressure.

FSM

IDLE --acl_r_fault--> GEN
GEN --mỗi RVALID && RREADY--> tăng beat_count
GEN --final handshake--> IDLE

Tại request fault, chốt ARID, ARLEN và ERR_MODE. GEN giữ RVALID cho tới handshake; counter không đổi khi RREADY thấp.

Payload local response

RID   = accepted ARID snapshot
RDATA = 32'h0000_0000
RRESP = ERR_MODE ? DECERR : OKAY
RLAST = (beat_count == ARLEN)

ARLEN đã là beats-minus-one nên final index bằng ARLEN. Không cộng/trừ lại trong so sánh RLAST.

Stable under stall

Nếu RVALID=1 và RREADY=0, RID/RDATA/RRESP/RLAST phải giữ nguyên. Tính RLAST từ counter chỉ an toàn khi counter chỉ tăng trên handshake.

Lab

  1. Test LEN=0 tạo đúng một beat với RLAST=1.
  2. Test LEN=15 tạo đúng 16 handshake.
  3. Randomize RREADY và dùng scoreboard đếm accepted beat.
  4. Stall đúng final beat; RLAST và payload phải giữ ổn định.
  5. Test DECERR và honeypot OKAY mode.
  6. Kiểm ARVALID downstream luôn 0 cho denied owner.

Exit gate

  • Read-drain unit tests PASS.
  • Số handshake chính xác cho LEN 0/15.
  • RLAST chỉ ở final beat.
  • RID/RRESP/RLAST stable dưới backpressure.

Câu hỏi kiểm tra

  1. Với ARLEN=15, final beat index là bao nhiêu?
  2. RREADY thấp có làm counter tăng không?
  3. Honeypot mode thay đổi response nhưng có được bỏ fault logging không?
